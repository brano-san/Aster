# Архитектура Aster

Aster — терминал на Rust с нативным GPU-рендерингом. Заметки к выпускам — в [docs/releases](docs/releases).

## Принципы

1. **Ядро без ввода-вывода.** Вкладки, панели, горячие клавиши, кодирование клавиш и мыши, выделение и построение кадра живут в `aster-core` и не делают системных вызовов. Наружу ядро говорит очередью эффектов (`Effect`), внутрь получает события (`Event`), поэтому сценарии целиком тестируются без окна и без PTY (`crates/aster-core/test/app.rs`).
2. **Ядро строит, платформа рисует.** Каждый кадр `App::frame` собирает `DrawList` (экземпляры по 64 байта), платформенный `Renderer` загружает новые глифы в атлас и рисует всё одним вызовом.
3. **UI-поток не ждёт PTY.** Чтение, разбор VT-потока и запись идут в отдельных потоках; UI-поток только берёт снимок экрана под коротким замком.
4. **Перерисовка только по изменению.** Флаг `dirty` ставят события, вывод PTY и мигание курсора; в остальное время цикл сообщений спит.

## Крейты

| Крейт | Назначение | Зависимости |
|---|---|---|
| `aster-gfx` | `Rect`, `Color`, `Instance`, `DrawList`, атлас полками, трейт `TextBackend` и `Gfx` (кэш разметки, глифов, метрик, очередь загрузок, `Gfx::cell` для клетки сетки), `Bitmap` | — |
| `aster-vt` | `Terminal` поверх `alacritty_terminal::Term`: подача байтов, размер, выделение, прокрутка, снимок видимых клеток, курсор; `Palette` (схемы Aster Dark и Aster Light, куб 256 цветов, жирный как яркий, dim, inverse); события `VtEvent` (ответы в PTY, заголовок, звонок, OSC 52) | `alacritty_terminal` |
| `aster-core` | `App` (вкладки, дерево панелей, сессии, мышь, выделение, селектор команд и профилей), `view` (геометрия заголовка и кадр), `keymap` (действия, привязки по умолчанию, аккорды), `keys` (кодирование клавиш xterm, мыши SGR и legacy, вставки), `config` (TOML), `panes`, `theme`, `overlay`, `fuzzy` | `aster-gfx`, `aster-vt` |
| `aster-platform` | трейты `Window`, `WindowHandler`, `WindowSystem`, `Renderer`, `Pty`, `Platform`; `SpawnRequest`, `Spawned` | `aster-core`, `aster-gfx` |
| `aster-platform-windows` | Win32-окно со своим заголовком, D3D11 + DirectComposition, DirectWrite с курсивом, ConPTY, автоопределение оболочек (PowerShell 5/7, CMD с PROMPT, сообщающим папку, WSL, Git Bash, Cygwin, MSYS2, VS Developer Prompt), открытие ссылок через `ShellExecuteW` | `windows` |
| `aster-platform-linux` | окно на winit 0.31 (Wayland и X11, без системной рамки: перетаскивание и изменение размера за край из кода, двойной щелчок по заголовку), OpenGL ES 3 через EGL (`glutin` + `glow`, шейдер WGSL → GLSL через `naga`), текст на `harfrust` + `swash` + fontconfig с синтетическим курсивом, PTY через `openpty` + `fork` + `execvpe`, оболочка входа из passwd и `/etc/shells`, буфер обмена через data transfer winit, `xdg-open` | `winit`, `glutin`, `glow`, `harfrust`, `swash`, `libc` |
| `aster-ssh` | разбор `~/.ssh/config` (`config::parse`, `config::resolve`), разрешение назначения (`destination`), собственный SSH-клиент (`client`, `console`, `secrets`), SFTP (`sftp`, рекурсивные операции `sftp_tree`), перенаправление портов (`forward`, разбор описаний и локальные/динамические циклы поверх абстрактного `Opener`; `socks` — серверная сторона SOCKS4/4a/5) | `russh` (бэкенд `ring`), `tokio`, `aster-proto` |
| `aster-zmodem` | ZMODEM без ввода-вывода: CRC-16/32, кодирование и потоковый разбор кадров, распознавание начала передачи в выводе (`detect`), приёмник и отправитель как конечные автоматы; проверяется передачей «отправитель → приёмник» в памяти | — |
| `aster-proto` | обработка потоков сессии без ввода-вывода: замена переводов строк, локальное эхо и построчный ввод (в том числе hex), hex-вид вывода, кавычки для путей под оболочку, распознавание запроса пароля, скрипты входа «ожидать → отправить», согласование Telnet (ECHO, SGA, TTYPE, NAWS) | `regex` |
| `aster-vault` | хранилище секретов: JSON, зашифрованный мастер-паролем (Argon2id + XChaCha20-Poly1305), строка `aster-vault:1:<base64>` | `argon2`, `chacha20poly1305` |
| `aster` | бинарник: `Handler` (окна, рендереры, применение эффектов), `Session` (потоки чтения, записи и ожидания PTY), конфиг и положение окна | все |

**Правило изоляции.** `aster-gfx`, `aster-vt`, `aster-core`, `aster-platform` не зависят от крейта `windows` (windows-rs). Исключение — `windows-sys`, который `alacritty_terminal` тянет для своего модуля `tty`; Aster этот модуль не использует. CI проверяет правило задачей `deps-isolation`. PTY — часть платформы (`Platform::spawn`), как окно и шрифты.

## Потоки

| Поток | Сколько | Что делает |
|---|---|---|
| главный (UI) | 1 | цикл сообщений Win32 для всех окон, `App`, кадр, вызовы D3D11 |
| `aster-pty-read-N` | по одному на сессию | читает выход ConPTY блоками до 64 КиБ, под `FairMutex` подаёт в `Terminal::feed`, будит UI |
| `aster-pty-write-N` | по одному на сессию | пишет в вход ConPTY из канала |
| `aster-pty-wait-N` | по одному на сессию | ждёт процесс, закрывает псевдоконсоль (чтобы поток чтения получил EOF) и отдаёт код выхода |

Пробуждение — `Win32Waker`: `WM_WAKE` скрытому окну-концентратору, повторные пробуждения схлопываются флагом.

## Путь «ввод → PTY → кадр»

1. Оконная процедура переводит сообщения в `Event`: `WM_KEYDOWN` → `Key`, `WM_CHAR` → `Char`, `WM_SYSCHAR` → `AltChar`, мышь, IME, фокус.
2. `App::on_event`: сначала горячие клавиши (`Keymap::press`, с аккордами), затем кодирование клавиши (`keys::encode_key`). Если клавиша порождает и `WM_CHAR` (Enter, Backspace, Tab, Esc, хоткеи с Ctrl), следующий `Char` проглатывается; сбрасывается флаг на каждом `KEYDOWN`.
3. `Effect::Write` уходит в канал потока записи. Ввод в панель, чья сессия ещё не запущена, копится и уходит сразу после `Effect::Spawn`.
4. Поток чтения подаёт вывод в `Terminal`; ответы терминала (DA, DSR, размер в пикселях) приходят через `VtEvent::Write` и пишутся обратно; заголовок, звонок и OSC 52 разбираются в `App::woken`.
5. Кадр: геометрия заголовка (`view::chrome`), раскладка панелей (`Node::layout`), для каждой панели — размер в клетках; новая панель получает `Effect::Spawn` с точным размером, изменившаяся — `Effect::Resize`. Клетки рисуются в два прохода: фоны и курсор-блок, затем глифы и подчёркивания (волнистое — свой вид экземпляра `UNDERCURL` в шейдере).

## Окно и заголовок

Полоса вкладок занимает область заголовка: `WM_NCHITTEST` спрашивает `App::hit_test`, пустое место — `HTCAPTION` (перетаскивание, Snap, двойной щелчок), кнопки — `HTMINBUTTON`/`HTMAXBUTTON`/`HTCLOSE` (Snap Layouts над «развернуть»). Положение окна сохраняется в `%APPDATA%\Aster\window.state` при закрытии и восстанавливается в пределах рабочей области монитора.

## Рендеринг

Одно устройство D3D11, swap chain `FLIP_DISCARD` для композиции, `SetMaximumFrameLatency(1)`, ожидание кадрового объекта вместе с вводом, синхронная перерисовка в `WM_SIZE`, восстановление после потери устройства. Шейдер `ui.hlsl` — виды: заливка и скруглённые рамки (SDF), глиф, цветной глиф, тень, волнистое подчёркивание. Атлас 2048² сбрасывается целиком при переполнении, кадр тут же строится заново.

Клетка сетки: ширина — округлённая ширина «M» моноширинного шрифта, высота — подъём + спуск + `line-padding`, поэтому глифы стоят в целых пикселях и не требуют субпиксельных копий. Резервные шрифты для символов, которых нет в основном, подбирает DirectWrite (на Linux — список fontconfig).

Псевдографика рисуется кодом (`aster-gfx/src/boxdraw.rs`): одинарные и жирные линии U+2500–257F, скругления, диагонали, блоки и штриховки U+2580–259F, треугольники Powerline E0B0–E0B3 растеризуются в маску ровно по размеру клетки и кладутся в тот же атлас (ключ — символ и размер клетки), поэтому стыкуются без щелей при любом `line-padding`. Двойные линии берутся из шрифта.

## Цветовые схемы, текущая папка, ссылки

- 191 встроенная схема лежит в `aster-vt/schemes` (формат Xresources), `build.rs` встраивает их; свои схемы — `[[color-schemes]]` в конфиге. Команда «Select color scheme» показывает схему при перемещении по списку, Esc возвращает прежнюю, Enter сохраняет конфиг.
- `aster-vt` сам разбирает OSC 7 (`file://`), OSC 9;9 и OSC 1337 `CurrentDir=`: `vte` их не обрабатывает. Новая вкладка и сплит стартуют в папке активной панели; для WSL unix-путь подставляется в аргумент `--cd`. CMD сообщает папку через переменную `PROMPT`, PowerShell — через обёртку функции `prompt`, которая передаётся в `-EncodedCommand` и выводит OSC 9;9 (профиль пользователя загружается раньше, так что его `prompt` сохраняется). Если оболочка папку не сообщает, папку её процесса читает платформа: на Windows из PEB процесса (`process.rs`), на Linux из `/proc/<pid>/cwd`. Для SSH и WSL этот путь не применяется: процесс там локальный, а папка удалённая. Тот же источник используется при сохранении сессии.
- Ссылки (`aster-core/src/links.rs`): URL, пути Windows и Unix у начала слова; при наведении — подчёркивание и курсор-рука, щелчок без выделения открывает (суффикс `:строка:столбец` отбрасывается).
- Конфиг перечитывается, когда окно получает фокус и файл изменился.
- Поиск (`aster-vt/src/search.rs`) держит индекс всех совпадений буфера с абсолютными номерами строк. Сдвиг строк при выводе отслеживается в `Terminal::feed`: пока история растёт — по её росту, когда история заполнена — по сигнатуре из трёх непустых строк экрана, найденной выше. Новый вывод индексируется инкрементально: в историю досканируются только строки, ушедшие с экрана, экран пересканируется целиком, совпадения, ушедшие за предел истории, отбрасываются; reflow и очистка истории перестраивают индекс заново. Текущее совпадение хранится в абсолютных координатах и остаётся на своём тексте, пока вывод идёт. Рисуются все видимые совпадения, текущее — цветом выделения с рамкой, метки всех совпадений — на правом краю панели, счётчик «N/M» — в панели поиска. Тест `search_stream.rs` проверяет: полный индекс 25 000 строк и кадр потокового вывода укладываются в 2 с и 20 мс даже в debug-сборке.
- SSH: хосты из `~/.ssh/config` становятся профилями «SSH: алиас», а строка `user@host:port` или `[ipv6]:port` в выборе профиля — пунктом «Connect to …». У таких профилей есть поле `ssh` (назначение) и запасная команда системного OpenSSH. По умолчанию (`ssh.client = "native"`) обработчик вместо процесса запускает собственный клиент `aster_ssh::client::start`: поток с однопоточным рантаймом tokio на соединение, наружу — `Connection` (вывод, ввод `Input::Data/Resize/Close`, код выхода), который `aster::remote` оборачивает в `Spawned`, так что дальше SSH-панель неотличима от локальной.
  - Назначение разрешается как в OpenSSH: `config::resolve` применяет все подходящие блоки, включая `Host *`; явные пользователь и порт важнее конфига; ключи — `IdentityFile` или `~/.ssh/id_ed25519`, `id_ecdsa`, `id_rsa`.
  - Транспорт: TCP (таймаут 15 с, keepalive 30 с), `ProxyCommand` (`%h %p %r %n %%`, через `cmd /C` без окна или `sh -c`), `ProxyJump` с цепочками: каждый узел — отдельное соединение со своей проверкой и входом, следующий идёт через `direct-tcpip`.
  - Вопросы задаются прямо в панели (`console::Console`): построчный ввод из `aster-proto`, пароли без эха, Ctrl+C или закрытие панели отменяют.
  - Ключ хоста сверяется с `~/.ssh/known_hosts`: известный — молча, новый — вопрос с отпечатком SHA256 и запись, изменившийся — предупреждение и отказ. Сертификаты хостов пока отклоняются.
  - Вход по очереди: агент (Windows: `\\.\pipe\openssh-ssh-agent`, затем Pageant; Unix: `SSH_AUTH_SOCK`), ключи с вопросом парольной фразы, keyboard-interactive, пароль (3 попытки); способы, которых нет в списке сервера, пропускаются.
  - Все соединения живут в одном многопоточном рантайме tokio (два рабочих потока). Пул (`ssh.share-connections`, по умолчанию включён) держит слабые ссылки на открытые соединения по ключу «пользователь, хост, порт, jump-узлы, ProxyCommand»: новая вкладка к тому же назначению открывает канал на уже вошедшем соединении без вопросов; ворота на ключ не дают двум вкладкам войти одновременно. Соединение закрывается (`disconnect`, затем jump-узлы), когда уходит последняя вкладка. Обработчик соединения держит консоль вкладки только слабой ссылкой, поэтому закрытая вкладка не держит свой вывод открытым.
  - Перенаправление портов: `LocalForward`, `DynamicForward` и `RemoteForward` из конфига разбирает `forward::parse` (ошибочные строки показываются в панели и пропускаются) и запускает новое соединение. Локальные и SOCKS-слушатели — `forward::start` с открывателем `Tunnel` (слабая ссылка на соединение, канал `direct-tcpip`); удалённые — `tcpip_forward` на сервере, а входящие каналы `forwarded-tcpip` клиент по порту соединяет с локальной целью. Слушатели живут вместе с соединением (`Conn::forwards`) и закрываются с ним; итог («Forwarding …», «SOCKS proxy on …», «The server listens on …») печатается в панель перед оболочкой.
  - Пароли и парольные фразы ключей (`ssh.remember-passwords`): клиент видит хранилище через трейт `aster_ssh::secrets::Secrets`, обработчик даёт системное (`Platform::secret_get/set/delete`: Windows — диспетчер учётных данных, цели `Aster/ssh:user@host:port` и `Aster/key:путь`; Linux — Secret Service через `secret-tool`, если он установлен). Сохранённое пробуется первым и молча; отвергнутое удаляется и спрашивается заново; после удачного ввода в панели предлагается сохранить. Тесты — на `secrets::Memory`.
  - Перенаправление агента: включается `ForwardAgent yes` для хоста или общей настройкой `ssh.forward-agent` (по умолчанию выключено). Клиент шлёт запрос на канале сессии, а входящий канал агента от сервера соединяет с локальным агентом (`IdentityAgent` из конфига, иначе канал OpenSSH на Windows или `SSH_AUTH_SOCK`); без разрешения канал отклоняется. `IdentityAgent none` отключает агента и для входа.
  - Файлы (SFTP): по первому запросу клиент открывает на том же соединении канал с подсистемой `sftp` (`russh-sftp`) и дальше обслуживает `Input::Sftp(sftp::Request)` отдельными задачами: список (папки первыми), скачивание в папку загрузок с нумерацией при совпадении имён, загрузка без перезаписи, папки, удаление, переименование; прогресс не чаще раза в 100 мс, отмена прерывает задачу, недокачанный файл удаляется. Ответы идут в `Connection::files`, обработчик пересылает их в `App::files_reply` через свой канал и будит окно.
  - Панель файлов (`aster-core::files`, `Ctrl+Shift+O`, пункт меню терминала) — страница поверх области вкладок, как настройки: путь, фильтр набором, строка «..», подсказки, передачи с полосой прогресса внизу. Ядро говорит своими типами `FileRequest`/`FileReply` через эффект `Effect::Files`, преобразование в типы `aster-ssh` — в `aster::remote`. Папку загрузок даёт `Platform::downloads_dir` (Windows: known folder Downloads; Linux: `XDG_DOWNLOAD_DIR`).
  - Папки целиком: скачивание и загрузка папки, удаление непустой папки и смена прав (F9, восьмерично, для папок рекурсивно) идут через `sftp_tree`; прогресс тех же `Progress`-ответов, не чаще раза в 100 мс. Список показывает права вида `rwxr-xr-x`.
  - «Править локально» (F4 или Ctrl+E в панели): `sftp::Request::Edit` скачивает файл в `%TEMP%/aster-edit/<id>/`, отвечает `Editing`, ядро открывает файл системной программой (`Effect::Open`), а задача раз в секунду сверяет время изменения и размер; изменившийся и затихший на секунду файл загружается обратно поверх оригинала (`Saved`). Кратковременное исчезновение файла (сохранение через переименование) пропускается. Щелчок по строке передачи останавливает слежение.
  - Перетаскивание файлов (Windows: `DragAcceptFiles`/`WM_DROPFILES` → `Event::DroppedFiles`): при открытой панели — загрузка в её папку, иначе пути вставляются в панель в кавычках по правилам её оболочки (`aster-proto::quote`), для WSL с переводом в `/mnt/<диск>/…`.
  - Тесты поднимают сервер russh на localhost: вопрос о хосте и пароль, ключ из конфига с парольной фразой, изменившийся ключ, отказ и закрытие панели, недоступный порт, цепочка через jump host.
- Восстановление сессии (`aster-core/src/session.rs`, настройка `recover-tabs`, по умолчанию включена): при закрытии последнего окна и при выходе из системы обработчик пишет `session.json` рядом с конфигом — окна, вкладки, дерево разделений с пропорциями, профиль, текущая папка и последние 1000 строк каждой панели (перенесённые строки склеены, чтобы заново перенестись под новую ширину). При запуске первое окно восстанавливает первую запись, для остальных открываются новые окна. Сохранённый текст выводится в терминал до старта оболочки; на Windows псевдоконсоль создаётся с `PSEUDOCONSOLE_INHERIT_CURSOR`: она спрашивает позицию курсора (DSR), эмулятор отвечает, и оболочка рисует с этой строки, не стирая восстановленный вывод. Закрытие последней вкладки сохраняет пустую сессию. В режиме захвата кадров сессия не читается и не пишется, если не задан `ASTER_CAPTURE_SESSION`.
- Режим Quake (`[appearance]`: `dock` = off/top/bottom/left/right, `dock-fill`, `dock-space`, `dock-always-on-top`, `dock-hide-on-blur`, `global-hotkey`, по умолчанию ``Ctrl-` ``): первое окно регистрирует глобальную клавишу на скрытом окне-концентраторе (`RegisterHotKey` с `MOD_NOREPEAT`), `WM_HOTKEY` приходит как `Event::GlobalHotkey`; обработчик прячет активное окно или показывает его, прикрепляя к краю рабочей области монитора под курсором (`aster_platform::dock_rect`). Настройки применяются заново при фокусе, если конфиг изменился. На Linux глобальная клавиша и прикрепление не поддерживаются: Wayland не даёт приложениям глобальных клавиш.
- Заголовок вкладки, равный пути к `.exe` (его ставит псевдоконсоль при старте), игнорируется — показывается имя профиля.

## Передача файлов в терминале (ZMODEM)

Поток чтения каждой сессии пропускает вывод через `aster::zmodem::Transfer`. Пока передачи нет, байты уходят в терминал без изменений; `aster_zmodem::frame::detect` находит начало: запрос на отправку от удалённой стороны (`sz`) запускает приёмник — файлы пишутся в папку загрузок с нумерацией при совпадении имён, ход и итог печатаются строками прямо в терминал; ожидание файлов (`rz`) переводит панель в режим выбора: ядро (`App::transfer_offered`) показывает полосу внизу панели, перетаскивание файлов или набранный путь дают `Effect::SendFiles`, Esc — `Effect::CancelTransfer`. Данные отправителя качает отдельный поток сессии, ожидая, пока очередь записи короче 64 кусков, так что большой файл не копится в памяти. Тесты гоняют контроллер против настоящих приёмника и отправителя из `aster-zmodem`.

## Конфигурация

`%APPDATA%\Aster\config.toml`, создаётся с умолчаниями при первом запуске. Разделы `[terminal]`, `[appearance]`, `[hotkeys]` (id действий и строки привязок: `"split-right" = ["Ctrl-Shift-S"]`), `[[profiles]]`. Умолчания: копирование при выделении, правый клик — копировать или вставить, 25 000 строк прокрутки.

Экран настроек (`Ctrl-,`, `aster-core::settings`) описан данными: каждый пункт `Setting` — раздел, путь ключа в TOML (`terminal.font-size`), подпись, подсказка и вид элемента (`Toggle`, `Choice`, `Schemes`, `Profiles`, `Number`, `Text`). Значения читаются и пишутся обобщённо через `toml::Value` (`settings::get`/`set`), так что новый пункт — одна строка в `SETTINGS`; тест проверяет, что каждый путь существует и его тип подходит элементу. Изменение сразу применяется через `App::set_config` и сохраняется эффектом `SaveConfig`; обработчик раздаёт конфиг остальным окнам и заново применяет закрепление и глобальную клавишу. Поиск фильтрует по всем словам запроса в подписи, подсказке, разделе и ключе. За пунктами `SETTINGS` в том же пространстве индексов идут действия (`settings::shortcut(i)`), раздел «Keyboard shortcuts»: Enter или щелчок включает захват, следующее сочетание становится единственной привязкой (`[hotkeys]` в конфиге), у других действий оно снимается с сообщением; Del очищает, Shift+Del возвращает умолчание. Пока идёт захват, клавиши (включая Ctrl+,) идут только в него. Раздел «Profiles» берёт снимок профилей (`ProfileRow`) при открытии и после каждой правки: Enter открывает форму (имя, команда, аргументы с кавычками, папка, SSH-назначение), для найденного профиля — копию с его окружением и значком; сохранение пишет `[[profiles]]` с id `custom:<имя>`, Ctrl+Enter делает профиль основным, Del удаляет свой профиль со второго нажатия.

Контекстные меню (`aster-core::menu`) — список `Entry` с действиями `Action`, поэтому каждый пункт доступен и из палитры команд, и через горячую клавишу; подсказка справа — текущая привязка. Меню вкладки открывается правым щелчком по ней (вкладка сначала становится активной, действия работают с активной), меню терминала — правым щелчком при `right-click = "menu"`. Двойной щелчок по вкладке или `rename-tab` открывает поле имени прямо во вкладке; своё имя хранится в `Tab::title`, пустое возвращает заголовок от оболочки, и оно переживает восстановление сессии.

Вставка нескольких строк (`aster-core::paste`) сначала показывает окно с превью и кнопками «вставить», «одной строкой», «отмена», но только если программа не включила bracketed paste: тогда оболочка выполнила бы каждую строку сразу. Отключается `terminal.warn-on-multiline-paste`.

Колокольчик (`terminal.bell`): `visual` — короткая подсветка панели (150 мс, таймер окна), `audible` — эффект `Beep`, системный звук через `Platform::beep`; где звука нет (Linux), обработчик вместо него подсвечивает панель. Звонки чаще раза в 250 мс сливаются в один. В фоновом окне дополнительно мигает кнопка на панели задач.

Прозрачность: цвета `DrawList` хранятся без предумножения, вершинный шейдер умножает цвет на альфу, смешивание `ONE, INV_SRC_ALPHA`, цепочка обмена DirectComposition создаётся с `DXGI_ALPHA_MODE_PREMULTIPLIED`, цвет очистки предумножается. App при создании и при смене `appearance.backdrop` выдаёт эффект `Surface`; окно отвечает `Window::set_surface`, что получилось: `translucent` (Windows — да, Linux — пока нет: нужен ARGB-конфиг EGL) и `backdrop` (Windows 11: `DWMWA_SYSTEMBACKDROP_TYPE` — Mica `MAINWINDOW`, Acrylic `TRANSIENTWINDOW`; Windows 10 отказывает). `App::restyle` даёт фону терминала альфу `appearance.opacity`, а полосе вкладок — 0 при материале, иначе ту же. Окно без поверхности перенаправления (`WS_EX_NOREDIRECTIONBITMAP`), поэтому материал виден сквозь прозрачные пиксели без `DwmExtendFrameIntoClientArea`; с расширением рамки DWM рисует под заголовком свои кнопки. Экран настроек, превью и поле переименования рисуются непрозрачным `theme.surface`.

## Linux

Окно без системной рамки: `HitArea::Caption` превращается в `drag_window`, полоса в 5 пикселей у края — в `drag_resize_window`, двойной щелчок по заголовку — в разворот, правый щелчок — в меню окна. Клавиши сопоставляются по позиции на US-раскладке (хоткеи работают на любой раскладке), текст берётся из `KeyEvent::text`; при зажатом Ctrl окно само порождает управляющий символ (Ctrl+C → 0x03), при Alt — `AltChar`. Буфер обмена асинхронный: `clipboard_text` просит winit прочитать данные, текст приходит событием `Pasted`. Таймер мигания курсора — `ControlFlow::WaitUntil`.

Устройство OpenGL ES одно на процесс и создаётся от дисплея цикла событий; на Wayland вертикальная синхронизация отключена (кадры темпирует композитор), на X11 — `SwapInterval::Wait(1)`. Иконки интерфейса — `AsterIcons.ttf` (подмножество Fluent UI System Icons на кодах Segoe Fluent), шрифт интерфейса по умолчанию — `AsterSans.ttf` (подмножество DejaVu Sans) или шрифт рабочего стола из GNOME/KDE.

## Проверка кадра без экрана

`ASTER_CAPTURE=путь.png` после каждого кадра пишет снимок и завершает процесс через `ASTER_CAPTURE_MS` (по умолчанию 4 с); на Windows окно открывается вне экрана, на Linux — обычным окном. Тест `crates/aster-platform-linux/test/render.rs` рисует кадр `App` на безоконном EGL-устройстве в offscreen-текстуру и с `ASTER_RENDER_PNG=путь` сохраняет его. `ASTER_CAPTURE_SIZE=900,520` задаёт размер, `ASTER_CAPTURE_KEYS` — ввод: `'текст` печатает символы, `Ctrl+Shift+S`, `Enter` и т. п. — клавиши. `Wait` делает паузу 1,5 с, `Click@x,y`, `RightClick@x,y`, `DoubleClick@x,y` и `MiddleClick@x,y` — щелчки в пикселях клиентской области (только Windows). Пример: `ASTER_CAPTURE_KEYS="'cd C:\Windows;Enter;Wait;Ctrl+Shift+D"`.

- `aster-gfx` — список примитивов, атлас и текстовый кэш.
