# Архитектура Aster

Aster — терминал на Rust с нативным GPU-рендерингом. Заметки к выпускам — в [docs/releases](docs/releases).

## Принципы

1. **Ядро без ввода-вывода.** Вкладки, панели, горячие клавиши, кодирование клавиш и мыши, выделение и построение кадра живут в `aster-core` и не делают системных вызовов. Наружу ядро говорит очередью эффектов (`Effect`), внутрь получает события (`Event`), поэтому сценарии целиком тестируются без окна и без PTY (`crates/aster-core/test/app.rs`).
2. **Ядро строит, платформа рисует.** Каждый кадр `App::frame` собирает `DrawList` (экземпляры по 64 байта), платформенный `Renderer` загружает новые глифы в атлас и рисует всё одним вызовом.
3. **UI-поток не ждёт PTY.** Чтение, разбор VT-потока и запись идут в отдельных потоках; UI-поток только берёт снимок экрана под коротким замком.
4. **Перерисовка только по изменению.** Флаг `dirty` ставят события, вывод PTY и мигание курсора; в остальное время цикл сообщений спит.

PTY — часть платформы (`Platform::spawn`), как окно и шрифты.

## Путь «ввод → PTY → кадр»

После распознавания ZMODEM читатель подаёт вывод в VT порциями до 8 КиБ, освобождая замок между ними. У окна один канал пробуждений ёмкостью в один сигнал для всех панелей и событий VT. Отдельный поток доставляет сигнал сразу или по истечении интервала в 8 мс, даже если чтение уже заблокировано в ожидании данных. После успешной отрисовки окно обновляет время кадра. При задержке от 100 мс читатель уступает 1 мс вне замка, а поток записи продолжает принимать ввод.

1. Оконная процедура переводит сообщения в `Event`: `WM_KEYDOWN` → `Key`, `WM_CHAR` → `Char`, `WM_SYSCHAR` → `AltChar`, мышь, IME, фокус.
2. `App::on_event`: сначала горячие клавиши (`Keymap::press`, с аккордами), затем кодирование клавиши (`keys::encode_key`). Если клавиша порождает и `WM_CHAR` (Enter, Backspace, Tab, Esc, хоткеи с Ctrl), следующий `Char` проглатывается; сбрасывается флаг на каждом `KEYDOWN`. При вводе в терминал `AltChar` с включённым `terminal.alt-is-meta` добавляет ESC перед символом UTF-8. Выключение параметра передаёт сам символ.
3. `Effect::Write` уходит в канал потока записи. Ввод в панель, чья сессия ещё не запущена, копится и уходит сразу после `Effect::Spawn`.
4. Поток чтения подаёт вывод в `Terminal`; ответы терминала (DA, DSR, размер в пикселях) приходят через `VtEvent::Write` и пишутся обратно; заголовок, звонок и OSC 52 разбираются в `App::woken`.
5. Кадр: геометрия заголовка (`view::chrome`), раскладка панелей (`Node::layout`), для каждой панели — размер в клетках; новая панель получает `Effect::Spawn` с точным размером, изменившаяся — `Effect::Resize`. Клетки рисуются в два прохода: фоны и курсор-блок, затем глифы и подчёркивания (волнистое — свой вид экземпляра `UNDERCURL` в шейдере).

## Окно и заголовок

Полоса вкладок занимает область заголовка: `WM_NCHITTEST` спрашивает `App::hit_test`, пустое место — `HTCAPTION` (перетаскивание, Snap, двойной щелчок), кнопки — `HTMINBUTTON`/`HTMAXBUTTON`/`HTCLOSE` (Snap Layouts над «развернуть»). При закрытии положение окна сохраняется в файле `window.state` рядом с конфигурацией. При запуске окно возвращается в пределы рабочей области монитора.

Плотность интерфейса (`appearance.density`, от 0,6 до 1,4 с шагом 0,1, по умолчанию 1,0) задаёт размер вкладок, кнопок окна, меню, строк настроек и отступов. Геометрия отрисовки и области нажатия используют один масштаб `App::ui()`, равный произведению DPI-масштаба на плотность. Метрики шрифта и ячеек терминала вычисляются по DPI и масштабу текста.

При `terminal.open-on-start = false` первое окно без восстановленного сеанса открывает стартовую страницу. Явная команда запуска или выбора профиля открывает запрошенную вкладку, а запрос вставки создаёт вкладку для ввода. Стартовая страница также появляется при закрытии последней вкладки, если `appearance.last-tab-closes-window = false`. Строки по центру позволяют открыть вкладку с основным профилем, один из пяти последних доступных профилей, полный селектор или настройки. Список поддерживает щелчок, стрелки и Enter. Сочетания перехода к вкладкам 1–5 на стартовой странице запускают соответствующие недавние профили.

В Windows настройка `appearance.tray` включает значок в области уведомлений. Его обслуживает скрытое окно процесса. Щелчок возвращает последнее активное окно или создаёт новое, если все окна закрыты. В контекстном меню доступны команды «Новое окно» и «Выйти». Пока значок активен, процесс продолжает работать после закрытия последнего окна. В Linux настройка не действует.

## Интеграция с рабочим столом

В Linux действие на странице «Приложение» устанавливает ярлык в XDG-каталог `applications` и значок в тему `hicolor`. Идентификатор Wayland и класс окна X11 совпадают с `aster.desktop`. Фоновый поток освежает установленный ярлык при запуске и изменении пользовательских профилей. Меню ярлыка открывает новое окно или вкладку с выбранным профилем.

Для выбора терминала по умолчанию ярлык объявляет аргументы запуска команды и рабочего каталога. Входы `-e` и `--` передают программу и аргументы в PTY отдельными строками через существующий протокол экземпляров. Путь из `--dir` или `--working-directory` разрешается относительно каталога вызывающего процесса.

Настройка `system.explorer-menu` управляет действием «Открыть в Aster» для папок. В Linux фоновый поток записывает отдельные файлы в пользовательском каталоге данных, а в общей конфигурации XML обновляет только элемент с идентификатором Aster. Отключение удаляет принадлежащие Aster записи.

Настройка `system.autostart` регистрирует запуск при входе пользователя. Windows хранит команду в значении `Aster` ключа `Run` в `HKCU`, Linux использует `autostart/aster.desktop` в XDG-каталоге конфигурации. При запуске запись синхронизируется с текущим путём к бинарнику. Для трея или режима прикрепления к краю добавляется `--hidden`. Windows держит стартовые окна скрытыми, Linux создаёт первое окно после запроса от другого экземпляра. При выключенных режимах окно открывается сразу.

## Рендеринг

Одно устройство D3D11, swap chain `FLIP_DISCARD` для композиции, `SetMaximumFrameLatency(1)`, ожидание кадрового объекта вместе с вводом, синхронная перерисовка в `WM_SIZE`, восстановление после потери устройства. Шейдер `ui.hlsl` — виды: заливка и скруглённые рамки (SDF), глиф, цветной глиф, тень, волнистое подчёркивание. Атлас 2048² разбит на полки. Глиф и его полка запоминают номер последнего кадра использования. Если свободного места нет, упаковщик освобождает одну или несколько соседних полок по давности использования. Полки с глифами, псевдографикой или изображениями текущего кадра защищены. Если все подходящие полки заняты текущим кадром, загрузка нового глифа откладывается до следующего обращения. После потери графического устройства атлас заполняется заново.

Клетка сетки: ширина — округлённая ширина «M» моноширинного шрифта, высота — подъём + спуск + `line-padding`, поэтому глифы стоят в целых пикселях и не требуют субпиксельных копий. Для символа, которого нет в основном шрифте, сначала проверяется семейство `terminal.fallback-font`, затем выполняется системный подбор. В Windows это таблица подстановок DirectWrite, в Linux файлы указанного семейства подбирает и открывает фоновый поток через fontconfig. Когда семейство готово, окно обновляет кэш разметки.

При включённом `terminal.ligatures` соседние клетки строки с одинаковым оформлением передаются в DirectWrite или HarfRust вместе с признаками OpenType `liga` и `calt`. Начало кластера привязывается к позиции клетки по байтовому смещению UTF-8, а внутренние смещения глифов сохраняются. Широкий символ занимает две клетки. Выделение и блочный курсор разделяют серии, фон и подчёркивания рисуются по клеткам. По умолчанию шейпинг выполняется по одной клетке с выключенными лигатурами.

Параметр `terminal.minimum-contrast-ratio` задаёт минимальный контраст текста по WCAG. Рендерер учитывает итоговые цвета клетки, в том числе инверсию, выделение, подсветку поиска и блочный курсор. Если контраста мало, цвет глифа приближается к белому или чёрному. При значении 1 сохраняется исходный цвет.

Псевдографика рисуется кодом (`aster-gfx/src/boxdraw.rs`): одинарные и жирные линии U+2500–257F, скругления, диагонали, блоки и штриховки U+2580–259F, треугольники Powerline E0B0–E0B3 растеризуются в маску ровно по размеру клетки и кладутся в тот же атлас (ключ — символ и размер клетки), поэтому стыкуются без щелей при любом `line-padding`. Двойные линии берутся из шрифта.

## Цветовые схемы, текущая папка, ссылки

- 191 встроенная схема лежит в `aster-vt/schemes` (формат Xresources). Скрипт сборки перечисляет файлы, а при компиляции `aster-vt` макрос `include_str!` читает их относительно `CARGO_MANIFEST_DIR`. Поэтому один и тот же сгенерированный список подходит для разных рабочих копий. Свои схемы задаются в `[[color-schemes]]` в конфиге. Команда «Select color scheme» показывает схему при перемещении по списку, Esc возвращает прежнюю, Enter сохраняет конфиг.
- `aster-vt` сам разбирает OSC 7 (`file://`), OSC 9;9 и OSC 1337 `CurrentDir=`: `vte` их не обрабатывает. Новая вкладка и сплит стартуют в папке активной панели; для WSL unix-путь подставляется в аргумент `--cd`. CMD сообщает папку через переменную `PROMPT`, PowerShell — через обёртку функции `prompt`, которая передаётся в `-EncodedCommand` и выводит OSC 9;9 (профиль пользователя загружается раньше, так что его `prompt` сохраняется). Если оболочка папку не сообщает, папку её процесса читает платформа: на Windows из PEB процесса (`process.rs`), на Linux из `/proc/<pid>/cwd`. Для SSH и WSL этот путь не применяется: процесс там локальный, а папка удалённая. Тот же источник используется при сохранении сессии.
- Ссылки (`aster-core/src/links.rs`): URL, пути Windows и Unix у начала слова; при наведении — подчёркивание и курсор-рука, щелчок без выделения открывает цель (суффикс `:строка:столбец` отбрасывается). `terminal.link-modifier` проверяется при нажатии левой кнопки мыши. Значение `none` допускает обычный щелчок, `ctrl` и `shift` требуют соответствующую клавишу.
- Конфиг перечитывается, когда окно получает фокус и файл изменился.
- Поиск (`aster-vt/src/search.rs`) держит индекс всех совпадений буфера с абсолютными номерами строк. Сдвиг строк при выводе отслеживается в `Terminal::feed`: пока история растёт — по её росту, когда история заполнена — по сигнатуре из трёх непустых строк экрана, найденной выше. Новый вывод индексируется инкрементально: в историю досканируются только строки, ушедшие с экрана, экран пересканируется целиком, совпадения, ушедшие за предел истории, отбрасываются; reflow и очистка истории перестраивают индекс заново. Текущее совпадение хранится в абсолютных координатах и остаётся на своём тексте, пока вывод идёт. Рисуются все видимые совпадения, текущее — цветом выделения с рамкой, метки всех совпадений — на правом краю панели, счётчик «N/M» — в панели поиска. Тест `search_stream.rs` проверяет: полный индекс 25 000 строк и кадр потокового вывода укладываются в 2 с и 20 мс даже в debug-сборке.
- SSH: хосты из `~/.ssh/config` становятся профилями «SSH: алиас». Поле `ssh` хранит назначение, например `user@host:port` или `[ipv6]:port`. При `ssh.client = "native"` обработчик передаёт в `aster::remote` параметры профиля и панели. Клиент возвращает `Connection` с каналами ввода, вывода и кодом выхода, а `aster::remote` оборачивает его в `Spawned`.
  - В таблице `[profiles.ssh-options]` задаются `user`, `port`, `identity-files`, `keepalive-ms`, `keepalive-count`, `ready-timeout-ms`, `skip-banner`, `term`, `remember-cwd` и `x11`. Значения профиля имеют приоритет. Затем берутся пользователь и порт из назначения, параметры подходящих блоков `~/.ssh/config` и умолчания клиента. При пустом имени пользователя панель спрашивает «Login as:». Список файлов ключей берётся из профиля или директив `IdentityFile`. Если список пуст, клиент проверяет существующие файлы в `~/.ssh` по порядку: `id_ed25519`, `id_ecdsa`, `id_rsa`.
  - В `[profiles.ssh-options.algorithms]` задаются массивы `kex`, `cipher`, `mac`, `host-key` и `compression` в порядке предпочтения. Пустой массив выбирает порядок библиотеки: первыми предлагаются ML-KEM с X25519 и Curve25519, ChaCha20-Poly1305 и AES-256-GCM, затем при выборе MAC предпочтение отдается вариантам EtM. Неизвестное имя вызывает предупреждение. Если из явно указанных имён ни одно не поддерживается, клиент сообщает об ошибке.
  - По умолчанию интервал keepalive равен 5000 мс, предел пропущенных ответов — 10, срок установления транспорта — 20000 мс. Нулевой интервал отключает keepalive. `skip-banner = true` скрывает приветствие сервера. Консоль выводит ход подключения приглушённым цветом, предупреждения жёлтым и ошибки красным. Настройка `ssh.clear-after-connect` по умолчанию очищает экран перед первым выводом оболочки.
  - Тип терминала для PTY берётся из `term`, затем из `SetEnv TERM=…`, затем из окружения панели (по умолчанию `xterm-256color`). При `remember-cwd = true` дубликат и восстановленная панель передают абсолютный путь, сообщённый оболочкой через OSC 7. Клиент экранирует путь и запускает оболочку входа из этой папки запросом `exec`. При отсутствии папки используется обычный запрос `shell`.
  - При прямом TCP, `ProxyCommand` и `ProxyJump` срок `ready-timeout-ms` охватывает открытие транспорта и обмен ключами. Для каждого промежуточного узла срок отсчитывается отдельно. Клиент сверяет ключ и выполняет вход на каждом узле, а следующий транспорт открывает через канал `direct-tcpip`. В `ProxyCommand` подставляются `%h %p %r %n %%`.
  - Вопросы задаются прямо в панели (`console::Console`): построчный ввод из `aster-proto`, пароли без эха, Ctrl+C или закрытие панели отменяют.
  - Ключ хоста сверяется с `~/.ssh/known_hosts`: известный — молча, новый — вопрос с отпечатком SHA256 и запись, изменившийся — предупреждение и отказ. Сертификаты хостов пока отклоняются.
  - Вход по очереди: агент (Windows: `\\.\pipe\openssh-ssh-agent`, затем Pageant; Unix: `SSH_AUTH_SOCK`), ключи с вопросом парольной фразы, keyboard-interactive, пароль (3 попытки); способы, которых нет в списке сервера, пропускаются.
  - Соединения работают в общем рантайме tokio с двумя рабочими потоками. Пул (`ssh.share-connections`, по умолчанию включён) повторно открывает каналы на соединениях с теми же пользователем, маршрутом, параметрами транспорта, ключами и перенаправлениями. На каждый ключ пула одновременно выполняется один вход. После закрытия последней вкладки клиент закрывает соединение и промежуточные узлы. Консоль исходной вкладки хранится по слабой ссылке.
  - Перенаправление портов: `LocalForward`, `DynamicForward` и `RemoteForward` из конфига разбирает `forward::parse` (ошибочные строки показываются в панели и пропускаются) и запускает новое соединение. Локальные и SOCKS-слушатели — `forward::start` с открывателем `Tunnel` (слабая ссылка на соединение, канал `direct-tcpip`); удалённые — `tcpip_forward` на сервере, а входящие каналы `forwarded-tcpip` клиент по порту соединяет с локальной целью. Слушатели живут вместе с соединением (`Conn::forwards`) и закрываются с ним; итог («Forwarding …», «SOCKS proxy on …», «The server listens on …») печатается в панель перед оболочкой.
  - При `ssh.remember-passwords` клиент предлагает сохранить введённый секрет через `aster_ssh::secrets::Secrets`. Хранилище Aster использует настроенный сейф или системное хранилище. Пароль адресуется по `ssh:user@host:port`, фраза ключа — по `key:SHA256:отпечаток` открытой части. Для формата со скрытой открытой частью хеш зашифрованного файла указывает на отпечаток. Старую запись `key:путь` клиент проверяет и переносит после успешной расшифровки. Перемещение файла сохраняет доступ к уже перенесённой фразе.
  - Перенаправление агента: включается `ForwardAgent yes` для хоста или общей настройкой `ssh.forward-agent` (по умолчанию выключено). Клиент шлёт запрос на канале сессии, а входящий канал агента от сервера соединяет с локальным агентом (`IdentityAgent` из конфига, иначе канал OpenSSH на Windows или `SSH_AUTH_SOCK`); без разрешения канал отклоняется. `IdentityAgent none` отключает агента и для входа.
  - Перенаправление X11 включается через `x11 = true` в профиле или `ForwardX11 yes` в конфигурации хоста. Локальный дисплей задаёт настройка `ssh.x11-display`; при пустом значении используется `DISPLAY`, а на Windows при его отсутствии — `localhost:0`. Клиент открывает TCP-соединение с `127.0.0.1:6000+n` или локальный сокет `/tmp/.X11-unix/X<n>` для дисплея `:n` на Linux. Для каждой SSH-сессии генерируется отдельный случайный cookie. Только после его проверки клиент обращается к локальному дисплею, подставляя его cookie из `XAUTHORITY` или `~/.Xauthority`. После закрытия вкладки её cookie перестаёт открывать новые каналы, даже если соседняя вкладка продолжает использовать то же SSH-соединение.
  - Файлы (SFTP): по первому запросу клиент открывает на том же соединении канал с подсистемой `sftp` (`russh-sftp`) и дальше обслуживает `Input::Sftp(sftp::Request)` отдельными задачами: список (папки первыми), скачивание в папку загрузок с нумерацией при совпадении имён, загрузка без перезаписи, папки, удаление, переименование; прогресс не чаще раза в 100 мс, отмена прерывает задачу, недокачанный файл удаляется. Ответы идут в `Connection::files`, обработчик пересылает их в `App::files_reply` через свой канал и будит окно.
  - Панель файлов (`aster-core::files`, `Ctrl+Shift+O`, пункт меню терминала) — страница поверх области вкладок, как настройки: путь, фильтр набором, строка «..», подсказки, передачи с полосой прогресса внизу. Ядро говорит своими типами `FileRequest`/`FileReply` через эффект `Effect::Files`, преобразование в типы `aster-ssh` — в `aster::remote`. Папку загрузок даёт `Platform::downloads_dir` (Windows: known folder Downloads; Linux: `XDG_DOWNLOAD_DIR`).
  - Папки целиком: скачивание и загрузка папки, удаление непустой папки и смена прав (F9, восьмерично, для папок рекурсивно) идут через `sftp_tree`; прогресс тех же `Progress`-ответов, не чаще раза в 100 мс. Список показывает права вида `rwxr-xr-x`.
  - «Править локально» (F4 или Ctrl+E в панели) скачивает файл в `%TEMP%/aster-edit/<id>/`. Перед ответом `Editing` задача запоминает время изменения, размер и хеш содержимого файла. Затем ядро открывает файл системной программой (`Effect::Open`). Задача раз в секунду сверяет эти три значения и загружает правку поверх оригинала, когда две проверки подряд видят одно и то же изменение (`Saved`). Так обнаруживаются и правки той же длины с прежней меткой времени. Кратковременное исчезновение файла при сохранении через переименование пропускается. Щелчок по строке передачи останавливает слежение. Подтверждение отмены приходит после завершения задачи слежения.
  - Перетаскивание файлов (Windows: `DragAcceptFiles`/`WM_DROPFILES` → `Event::DroppedFiles`): при открытой панели — загрузка в её папку, иначе пути вставляются в панель в кавычках по правилам её оболочки (`aster-proto::quote`), для WSL с переводом в `/mnt/<диск>/…`.
  - Тесты поднимают сервер russh на localhost: вопрос о хосте и пароль, ключ из конфига с парольной фразой, изменившийся ключ, отказ и закрытие панели, недоступный порт, цепочка через jump host.
- Восстановление сессии (`aster-core/src/session.rs`, настройка `recover-tabs`, по умолчанию включена): при закрытии последнего окна и при выходе из системы обработчик пишет `session.json` рядом с конфигом — окна, вкладки, дерево разделений с пропорциями, профиль, текущая папка и последние 1000 строк каждой панели (перенесённые строки склеены, чтобы заново перенестись под новую ширину). При запуске первое окно восстанавливает первую запись, для остальных открываются новые окна. Сохранённый текст выводится в терминал до старта оболочки; на Windows псевдоконсоль создаётся с `PSEUDOCONSOLE_INHERIT_CURSOR`: она спрашивает позицию курсора (DSR), эмулятор отвечает, и оболочка рисует с этой строки, не стирая восстановленный вывод. Закрытие последней вкладки сохраняет пустую сессию. В режиме захвата кадров сессия не читается и не пишется, если не задан `ASTER_CAPTURE_SESSION`.
- Режим Quake (`[appearance]`: `dock` = off/top/bottom/left/right, `dock-fill`, `dock-space`, `dock-always-on-top`, `dock-hide-on-blur`, `global-hotkey`, по умолчанию ``Ctrl-` ``): первое окно регистрирует глобальную клавишу на скрытом окне-концентраторе (`RegisterHotKey` с `MOD_NOREPEAT`), `WM_HOTKEY` приходит как `Event::GlobalHotkey`; обработчик прячет активное окно или показывает его, прикрепляя к краю рабочей области монитора под курсором (`aster_platform::dock_rect`). Настройки применяются заново при фокусе, если конфиг изменился. На Linux глобальная клавиша и прикрепление не поддерживаются: Wayland не даёт приложениям глобальных клавиш.
- Заголовок вкладки, равный пути к `.exe` (его ставит псевдоконсоль при старте), игнорируется — показывается имя профиля.

## Язык интерфейса

`aster-core::i18n`: исходный текст строк — английский, он же ключ каталога. Русский каталог `crates/aster-core/locales/ru.toml` встроен через `include_str!` и разбирается один раз. `t(text)` возвращает перевод текущего языка или сам текст, `tf(text, &[("name", value)])` дополнительно подставляет `{name}`. Строки меню, настроек, палитры и подписи действий хранятся по-английски и переводятся при отрисовке, поэтому смена языка действует сразу. Настройка `appearance.language`: `auto` (по умолчанию) берёт язык из `Platform::ui_language()` — на Windows первый предпочитаемый язык интерфейса, на Linux `LC_ALL`/`LC_MESSAGES`/`LANG`, — либо задаётся явно `en`/`ru`. Палитра команд в русском режиме находит действие и по английской подписи. Тест `test/i18n.rs` разбирает исходники ядра и требует перевода для каждой строки, переданной в `t`/`tf`, и для всех подписей из таблиц настроек, действий и меню.

## Хозяин терминалов и вкладки администратора

`aster_platform::host` — протокол между окном и отдельным процессом, который держит оболочку: кадры «вид (1 байт), длина (4 байта), данные» — приветствие с токеном, запрос запуска, готовность с pid, данные в обе стороны, размер, завершение, код выхода, ошибка. `host::client` превращает соединение в обычный `Spawned`, `host::serve` запускает оболочку через `Platform::spawn` и передаёт её; если клиент пропал, оболочка завершается. Направления идут по двум каналам: на Windows синхронные чтение и запись на одном канале блокируют друг друга.

Вкладка администратора на Windows (`new-admin-tab`, «Duplicate as administrator» в меню вкладки): окно остаётся обычным процессом, а `Platform::spawn_elevated` создаёт два именованных канала с уникальными именами, запускает себя через `ShellExecuteEx` с глаголом `runas` как `aster --host <имя> <токен>` (запрос UAC) и ждёт подключения до двух минут. Помощник без окна подключается к каналам и обслуживает оболочку с правами администратора; случайный токен не даёт другому процессу встать на его место. Запуск идёт в фоновом потоке, чтобы окно не замирало на время диалога UAC; отказ пользователя показывается в панели. Флаг `Profile::elevated` не сохраняется и сбрасывается при восстановлении сессии, чтобы запуск не начинался с запроса UAC. Заголовок вкладки получает приставку «Administrator:». На Linux `spawn_elevated` отказывает.

## Последовательные порты

При запуске найденные порты становятся профилями «Serial: COM3 (описание)» со спецификацией `COM3:115200,8N1` в поле `serial`. Свой профиль с другой скоростью, кадром или управлением потоком создаётся в настройках (поле «Serial port»).

В профиле со знаком вопроса вместо скорости, например `COM3:?,7E2,rtscts`, запуск остаётся в панели до выбора скорости. При открытии выделено 115200 бод. Можно выбрать одно из 14 значений или ввести своё от 50 до 4000000 бод. Enter подтверждает выбор, Esc закрывает ожидающую панель. Выбранная скорость подставляется только в этот запуск. В открытой последовательной панели команды `serial-speed` и `serial-break` доступны из палитры, контекстного меню и через назначенные сочетания клавиш. Обработчик окна передаёт их писателю порта через канал панели.

Флаг `,slow` в конце спецификации (например, `COM3:9600,8N1,slow`) включает побайтовую запись с паузой 2 мс. Во время длинной передачи поток записи продолжает обрабатывать смену скорости, сигнал BREAK и закрытие.

Адаптер `aster::serial` открывает порт через `aster_serial::session::open` в фоновом потоке. При первом неудачном запуске панель показывает причину ошибки. Если драйвер отклонил смену скорости или BREAK, причина появляется в панели, работа с портом продолжается. При потере открытого порта панель сохраняет вывод и показывает приглушённую подсказку. Enter повторяет подключение с параметрами этой линии и последней подтверждённой драйвером скоростью, Esc закрывает панель. Если устройство ещё недоступно, попытку можно повторить.

## Telnet и raw TCP

Профиль с полем `socket` (`telnet://host:23` или `tcp://host:port`; в настройках — поле «Telnet or TCP address», адрес нормализуется `aster_proto::address::parse`) подключается через `aster_net::session::open`, а обработчик оборачивает соединение в `Spawned` (`aster::net`): изменение размера панели уходит на сервер пакетом NAWS, закрытие панели закрывает сокет. Адрес со схемой, набранный в выборе профиля (Ctrl+Shift+E), предлагается первым пунктом «Подключиться к …» и открывает вкладку без сохранения профиля; профиль панели целиком попадает в восстановление сессии. Закрытие соединения сервером завершает панель с кодом 0, ошибка подключения или обрыв выводятся в панель, и она остаётся до нажатия клавиши: `wait` возвращает код только после того, как весь вывод сессии прочитан.

## Обработка потока и скрипты входа

Таблица `[profiles.stream]` профиля настраивает обработку между сессией и терминалом для любого типа панели, кроме вкладок администратора: `input` = normal / echo / line / line-hex, `output` = normal / hex, `newlines-in` и `newlines-out` = keep / strip / cr / lf / crlf / implicit-cr / implicit-lf, `backspace` = backspace / ctrl-h / ctrl-? / delete и шаги входа `[[profiles.stream.login]]` (`expect`, `send` с экранированием `\r`, `\x1b`, `\u0444`, `regex`, `optional`). Без таблицы или со значениями по умолчанию `Spawned` не оборачивается. Иначе `aster::stream::wrap` ставит писатель `Outgoing` (эхо уходит отдельным каналом в вывод) и поток чтения `Incoming`: скрипт входа видит сырой вывод без управляющих последовательностей и отвечает прямо в сессию, а в терминал идёт преобразованный вывод. Ошибка в регулярном выражении скрипта выводится красной строкой, сессия продолжается без скрипта. Для Telnet и raw TCP собственное эхо `aster-net` выключается, если режим ввода не normal. Для SSH, сети и последовательного порта эти параметры доступны на вкладке «Поток» редактора профиля.

У `Spawned` два писателя: `writer` для клавиш и необязательный `raw` для байтов, которые нельзя менять. `Session` пишет нажатия в `writer`, а данные ZMODEM — в `raw` (если его нет, тоже в `writer`), одним потоком записи, так что порядок сохраняется. `aster::net` отдаёт `raw` как `Input::Raw` (без эха и без CR LF, для Telnet только с удвоением IAC), `aster::stream::wrap` пускает в `raw` данные передачи и ответы скрипта входа мимо `Outgoing`. Входящий поток проходит `Incoming` раньше распознавания ZMODEM, поэтому с `newlines-in` или `output = "hex"` приём файлов не работает.

## Пароли в приглашениях (sudo и другие)

`aster-core::sudo`: после каждого пробуждения ядро смотрит текст перед курсором каждой панели (`Terminal::prompt_line`) и проверяет его `aster_proto::prompt::is_password_prompt`. Найдя приглашение, спрашивает обработчик эффектом `CheckSecret`, есть ли сохранённый пароль для ключа `sudo:<назначение SSH>` или `sudo:<id профиля>`. Если есть, полоса внизу панели предлагает Ctrl+Shift+Enter (`fill-password`) — обработчик читает пароль через `aster::secrets::Secrets` и пишет его в сессию с переводом строки; в ядро пароль не попадает. Если нет, ядро запоминает набранное в ответ (`note_input`, с Backspace и Ctrl+U); когда приглашение исчезло, повтора нет и в последних строках нет признаков ошибки («sorry», «incorrect», «failure»…), полоса предлагает сохранить (`SaveSecret`), а любая другая клавиша предложение снимает. Отключается `terminal.sudo-passwords`.

## Хранилище секретов в приложении

Пока `vault.sealed` пуст, пароли SSH, парольные фразы ключей и пароли для приглашений сохраняются в системном хранилище. После создания хранилища на странице «Хранилище» новые записи попадают в зашифрованную строку `vault.sealed` в `config.toml`. Рабочий поток открывает и запечатывает её через `aster_vault::Vault`. Все окна и SSH-сессии используют одно состояние разблокировки. При блокировке чтение возвращает пустой результат, а изменения ждут в памяти следующей успешной разблокировки.

Срок отсчитывается от момента разблокировки. `vault.remember-minutes` по умолчанию равен 15, при 0 после ввода остаются только метаданные списка. Для просмотра значения, изменения и экспорта требуется повторный ввод мастер-пароля. При обращении из SSH или явном заполнении sudo обработчик ставит такой запрос в очередь окна. Расшифрованные значения и пароль не остаются в состоянии рабочего потока между запросами. Страница получает только типы и подписи записей и фильтрует список по запросу. Меню открывают диалоги с подтверждением для удаления и стирания. Поля мастер-пароля маскируются и при необходимости показывают введённое значение. Просмотр записи запрашивает значение у рабочего потока и позволяет явно скопировать его в буфер обмена. Ответы привязаны к окну и диалогу; блокировка закрывает просмотр. Стирание очищает `vault.sealed` и возвращает сохранение паролей в системное хранилище.

Запись хранилища содержит тип, подпись, стабильный ключ поиска и значение. Старые записи получают тип и подпись при чтении по префиксу ключа. SSH может получить содержимое закрытого ключа по его отпечатку или подписи через `Secrets::key_file`.

Рабочий поток хранилища проверяет доступ к записи для просмотра и экспорта, сохраняет переименование без смены ключа поиска и запечатывает замену и удаление перед публикацией изменений. Экспорт создаёт новый файл. В Linux права доступа задаются при создании. При смене мастер-пароля перешифровываются все записи.

При включении `vault.encrypt-config` весь `config.toml` заменяется версионированным JSON-конвертом с шифротекстом. Рабочий поток хранит ключ конверта на время работы процесса, чтобы обычные сохранения оставались зашифрованными после блокировки списка секретов. Каждая запись использует новый nonce. Чтение перед записью и замена файла выполняются под межпроцессной блокировкой, общей для всех экземпляров Aster. Смена мастер-пароля обновляет оба уровня шифрования одной атомарной заменой файла. Отключение шифрования или стирание хранилища записывает обычный TOML.

До открытия вкладок зашифрованная конфигурация запрашивает мастер-пароль в первом видимом окне, в том числе при запуске с `--hidden`. Настройки меню приложений, файлового менеджера и автозапуска применяются после расшифровки. Ключ выводится в рабочем потоке; после ошибки фокус остаётся в поле. Отмена запускает настройки по умолчанию и исключает запись исходного файла до следующего запуска. Страница «Файл настроек» показывает состояние «Зашифрован».

## Передача файлов в терминале (ZMODEM)

Поток чтения каждой сессии пропускает вывод через `aster::zmodem::Transfer`. Пока передачи нет, байты уходят в терминал без изменений; `aster_zmodem::frame::detect` находит начало. Ядро знает состояние передачи панели (`PaneTransfer`: `AwaitingFiles`, `Incoming`, `Running`) и рисует полосу внизу панели. Если удалённая сторона хочет отправить файлы, контроллер копит её байты и спрашивает (`Incoming`): Enter (`Effect::AcceptTransfer`) запускает приёмник — файлы пишутся в папку загрузок с нумерацией при совпадении имён, ход и итог печатаются строками в терминал; Esc или Ctrl+C отказывают. Если удалённая сторона ждёт файлы (`AwaitingFiles`), перетаскивание или набранный путь дают `Effect::SendFiles`, Esc — `Effect::CancelTransfer`. Пока идёт передача (`Running`), клавиши в удалённую сторону не уходят, Esc и Ctrl+C отменяют, недокачанный файл удаляется. Что пришло в одном куске после конца передачи, доходит до терминала: `Receiver::rest`/`Sender::rest` отдают непрочитанный хвост, а контроллер срезает только завершающие байты протокола (конец последней строки заголовка и два `O`), даже если они пришли следующим куском. Данные отправителя качает отдельный поток сессии, ожидая, пока очередь записи короче 64 кусков, так что большой файл не копится в памяти. Тесты гоняют контроллер против настоящих приёмника и отправителя из `aster-zmodem`.

## Вкладки, панели и выделение

- Закреплённые вкладки образуют группу в начале полосы. Действие `pin-tab` и пункт меню меняют закрепление; клавиши перемещения и перетаскивание сохраняют границу группы. Закреплённая вкладка занимает 48 логических пикселей, показывает номер, значок профиля и цвет. Полное название активной вкладки остаётся в заголовке окна. Групповое закрытие пропускает закреплённые вкладки, индивидуальное запрашивает подтверждение. Поле `TabState.pinned` сохраняется в сеансе и при повторном открытии закрытой вкладки; у старых снимков значение по умолчанию — false.
- На странице «Внешний вид» `appearance.tab-index` добавляет номер перед названием, а `appearance.tab-close-buttons` управляет крестиками. Средняя кнопка мыши и Ctrl+Shift+W закрывают вкладку при любом значении. В полноэкранном режиме обработчик окна передаёт состояние в ядро; по умолчанию панели занимают всё окно, а `appearance.tabs-in-fullscreen` сохраняет обычные правила показа полосы. Если выключить `appearance.last-tab-closes-window`, после закрытия последней вкладки в том же окне открывается выбор профиля.
- `appearance.tab-width` задаёт ширину горизонтальных вкладок: `fit` сохраняет обычное распределение, `fixed` задаёт 200 логических пикселей. При нехватке места обычные вкладки сужаются до 84 логических пикселей. При переполнении активная вкладка остаётся видимой.
- `appearance.tab-bar-position` размещает вкладки у верхнего, нижнего, левого или правого края окна. Для нижней полосы и боковых списков сверху остаётся заголовок высотой 32 логических пикселя с областью перетаскивания и кнопками окна. Боковой список занимает 220 логических пикселей при достаточной ширине окна. Отрисовка, выбор вкладки, перенос и размещение панелей используют общую геометрию `Chrome`.
- При включённом `appearance.mru-tabs` сочетания Ctrl+Tab и Ctrl+Shift+Tab перебирают список недавно активных вкладок. Пока Ctrl удерживается, список в центре окна подсвечивает кандидата; отпускание Ctrl применяет выбор, Esc отменяет. История хранит постоянные идентификаторы вкладок и переживает перемещение вкладки и смену панели. По умолчанию сочетания переключают соседние вкладки.
- Пункт «Уведомить о завершении команды» запускает фоновую проверку дочерних процессов локальных оболочек вкладки. Первая проверка начинается сразу, следующие — с интервалом в две секунды. После перехода от занятого состояния к пустому списку процессов ядро однократно выдаёт `Effect::Attention` и отмечает вкладку точкой до следующего выбора. Отложенный ответ для отменённого запроса или закрытой вкладки отбрасывается.
- Выделение: одиночный щелчок — поток, двойной — слово по разделителям `terminal.word-separator` (передаются в `semantic_escape_chars`), тройной — строки, Alt при нажатии — блок, Shift — расширение текущего выделения. Модификаторы приходят событием `Event::Modifiers`: Windows шлёт его при нажатии и отпускании модификаторов, перед нажатием кнопки мыши и вращением колеса, Linux — по `ModifiersChanged`. С Shift щелчок не уходит в приложение, захватившее мышь.
- После горячей клавиши ядро глотает только тот символ, который она сама могла породить (управляющий или символ той же клавиши), поэтому первая буква после сочетания без символа (Ctrl+,) не теряется.
- Закрытая вкладка сохраняется снимком в формате восстановления сеанса (`TabState`: раскладка, профили, папки, хвост вывода, заголовок, цвет); `reopen-tab` строит её заново, хранится до 10 вкладок. `toggle-last-tab` помнит панель прежней активной вкладки: `track_tab` после каждого события сравнивает активную вкладку с прошлой.
- `explode-tab` переносит панели вкладки в отдельные вкладки, `combine-tabs` собирает все вкладки в одну равными колонками; терминалы при этом не перезапускаются. Alt+Shift+стрелки двигают ближайший разделитель нужной оси на 0,1 (`Node::nudge`).
- Широковещательный ввод (`pane-focus-all`, `focus-all-tabs`): `write_focused` пишет во все живые панели активной вкладки или всех вкладок, на каждой такой панели внизу полоса, щелчок по ней выключает режим.
- Активность и прогресс: `Terminal::output_seq` растёт с каждым выводом, панель помнит просмотренное значение (`seen`, обновляется в кадре для активной вкладки и после восстановления буфера); у фоновой вкладки с непросмотренным выводом точка перед заголовком. OSC 9;4 (`Terminal::progress`: normal, error, indeterminate, paused) рисуется полоской под заголовком вкладки, а прогресс активной вкладки уходит эффектом `Effect::Progress` в `Window::set_progress` — на Windows это `ITaskbarList3`, на Linux пока ничего.
- Цвет вкладки — пресет из `set-tab-color` или `color` профиля активной панели, полоска сверху вкладки.
- Подтверждение закрытия (`terminal.confirm-close`): перед закрытием панели, вкладок или окна ядро спрашивает пробу `Platform::child_processes` (Windows — снимок Toolhelp без conhost и процессов с именем самой оболочки, Linux — `/proc/*/stat`) по pid оболочек; если что-то запущено, показывается диалог со списком программ. Групповое закрытие спрашивает один раз. Перед закрытием окна ядро запоминает снимок (`session_snapshot`), и сеанс сохраняется из него, когда окно действительно закрывается. Завершение сеанса Windows не спрашивает.
- `terminal.focus-follows-mouse` переводит фокус на панель под указателем, если нет перетаскивания и модальных окон.
- Выбор профиля (`aster_core::picker`): пункты оверлея (`Pick`) несут группу, ранг, плашку и цвет. Порядок разделов: «Недавние» (`terminal.recent-profiles`, список общий для окон: `Effect::RecentProfiles` → обработчик раздаёт его всем окнам и хранит в `session.json`), «Мои профили», группы из поля `group` профиля по алфавиту, «Встроенные», «Из ~/.ssh/config», «Последовательные порты», затем «Управление профилями» (открывает настройки на строке профилей). При поиске пункты сортируются по рангу раздела, внутри — по совпадению; поиск идёт и по описанию (команде или адресу). Заголовок раздела рисуется перед первой строкой раздела и перед первой видимой строкой при прокрутке. Плашка — короткая метка по типу или значку профиля (PS, C:, WSL, Git, VS, SSH, COM, TN, TCP), цвет — из `color` профиля или по типу. Backspace при пустом поле подставляет адрес выбранного профиля для правки.
- Полоса вкладок (`appearance.tab-bar` = always / auto / never, переключатель `toggle-tab-bar`, Ctrl+Shift+B): без полосы `bare_chrome` отдаёт всё окно под панели, кнопок окна и заголовка нет, `hit_test` везде отвечает `Client`. При смене вкладки без полосы сверху на 1,2 с показывается «номер / всего  название». На Linux окно и так без системных декораций, поэтому в тайлинговом композиторе остаётся только терминал.

## Профили: группы, умолчания, шаблоны, раскладки

- Поле `on-exit` задаёт поведение панели после завершения сеанса. При `auto` успешный выход закрывает обычную панель, а запущенная разовая команда сохраняет вывод. При `keep` панель ждёт клавишу, при `close` закрывается с любым кодом. При `reconnect` соединение SSH, последовательного порта, Telnet или TCP запускается повторно через секунду в той же панели. Нажатие клавиши во время ожидания отменяет попытку. Новое соединение получает свежий разборщик VT, видимый текст и историю предыдущего сеанса. Для локальной оболочки `reconnect` действует как `keep`.
- Клавиша H на строке профиля переключает его видимость. Для своего профиля настройка хранится в `hidden`, для обнаруженного — в корневом списке `hidden-profiles` по идентификатору. Селектор и недавние профили учитывают видимость. Скрытый профиль доступен из командной строки и остаётся в настройках с отметкой «скрыт».
- Записи `[[groups]]` задают имя, идентификатор, родителя, цвет и значок. Поле `group` профиля ссылается на имя. Селектор показывает путь «Родитель › Группа». Старое имя группы без отдельной записи по-прежнему образует раздел. Поиск родителей завершается также при оборванной ссылке или цикле.
- Настройка `picker.quick-connect` задаёт протокол для адреса без префикса (`ssh` по умолчанию, `telnet`, `tcp`, `serial`). Префиксы `ssh://`, `telnet://`, `tcp://` и `serial:`, а также вид `COM3@9600` и `/dev/ttyUSB0@115200`, выбирают протокол явно. Селектор разбирает адрес общими парсерами и открывает разовую вкладку; запись в список профилей не добавляется.
- Действия `profile.<id>`, `profile-selector.<раздел>` и `group-selector.<id>` доступны в палитре и в подразделе «Профили» страницы горячих клавиш. Первое открывает вкладку, остальные ограничивают селектор источником (`own`, `built-in`, `ssh-config`, `serial-ports`) или группой со всеми её потомками. Привязки используют постоянные идентификаторы, подписи — имена профилей и групп. PageUp и PageDown перелистывают список. Backspace при пустом запросе переносит адрес выбранной строки в поле ввода. Для последовательного порта добавляется префикс serial:, а для SSH вне основного селектора и при другом провайдере по умолчанию — ssh://.
- При создании панели `profile::effective` применяет общие параметры из `[profile-defaults.<тип>]`, затем параметры групп от родителя к потомку и поля самого профиля. Поддерживаются типы `local`, `ssh`, `serial` и `socket`. Окружение объединяется по именам переменных, настройки потока и SSH — по отдельным полям. Профиль может переопределить папку, схему, цвет и режим выхода, в том числе явно вернуть `auto`. Панель отдельно хранит исходный профиль для следующего запуска и снимка сеанса.
- На странице «Профили» выбор основного профиля записывается в `terminal.profile`. Ниже `profiles_page` строит дерево групп по именам внутри каждого уровня. За своими профилями идут встроенные, узлы из `~/.ssh/config` и обнаруженные порты. Щелчок или Enter сворачивает ветку. Поиск временно раскрывает путь к каждому совпадению. По F5 или кнопке запуска профиль открывается в новой вкладке, настройки остаются на экране.
- Редактор группы позволяет выбрать родителя, цвет и значок. Потомки исключены из выбора родителя. При переименовании обновляются ссылки профилей и дочерних групп. Двойное нажатие Del переносит профили удаляемой группы в раздел «Без группы», а дочерние группы поднимает на уровень выше.
- Строка «Новый профиль» открывает выбор из пяти шаблонов. В редакторе вкладка «Общие» задаёт имя, группу, оформление, видимость и действие после выхода. Остальные вкладки определяются типом профиля. Для локальной команды доступны рабочая папка, строки окружения и запуск с повышенными правами в Windows (`admin`), для SSH — параметры соединения и файлы ключей, для последовательного порта — скорость и формат кадра, для сети — адрес. Редактор и драйвер порта используют общий разбор и форматирование спецификации из `aster_proto::serial`. Знак `?` вместо скорости откладывает её выбор до подключения. В трёх позициях формата кадра `?` обозначает наследование соответствующего параметра: например, `7??` задаёт только число бит данных. Вкладка «Поток» у удалённых профилей содержит режимы ввода и вывода, переводы строк, Backspace и шаги сценария входа. Ctrl+Tab и Ctrl+Shift+Tab переключают вкладки, Tab перемещает фокус по полям. Enter на встроенном профиле создаёт редактируемую копию.
- Общие параметры каждого типа редактируются внизу страницы, а параметры отдельной группы — в её редакторе. Они хранятся соответственно в `[profile-defaults.<тип>]` и `[groups.defaults.<тип>]`. Сброс удаляет запись выбранного типа, после чего при запуске действуют унаследованные значения. Действие `save-as-profile` сохраняет профиль текущей панели с её рабочей папкой.
- Действие `split-layout` сохраняет направления и пропорции разделителей, идентификаторы профилей и папки панелей. Для разовой команды или подключения без записи в конфигурации создаётся скрытый профиль. При открытии раскладки ядро сначала разрешает все ссылки, затем передаёт дерево в `App::build`, общий механизм восстановления сеансов. Если ссылка стала недоступной, ядро показывает её идентификатор. Значок ▦ и подпись «Раскладка» отличают такой профиль в селекторе.

## Командная строка и единственный экземпляр

`aster::cli` разбирает аргументы: без аргументов — окно, `[open] DIR` (относительный путь — от папки вызова), `run [--] CMD ARGS`, `profile NAME`, `paste TEXT`, `paste-path PATH`, `url URL`, `--version`, `--help` (на Windows вывод идёт в консоль родителя через `AttachConsole`). Запрос (`cli::Request`: команда и папка вызова, JSON) уходит в уже работающий Aster: `Platform::instance_listen` делает процесс первичным (Windows — именованный канал `aster-instance-<пользователь>-<сеанс>` с `FILE_FLAG_FIRST_PIPE_INSTANCE`, `PIPE_REJECT_REMOTE_CLIENTS`, следующий экземпляр канала создаётся до закрытия текущего; Linux — Unix-сокет `aster-instance.sock` в `XDG_RUNTIME_DIR` с правами 0600), а если первичный уже есть, `instance_send` передаёт запрос и процесс выходит. Первичный читает запросы в потоке, будит цикл окна, и обработчик выполняет их в последнем активном окне: новое окно, вкладка в папке, вкладка-команда, профиль по id или имени, вставка в активную вкладку; окно показывается и активируется. Запрос, с которым запущен сам первичный, выполняется при создании первого окна. Вкладка-команда (`Profile::hold`) после успешного завершения остаётся с сообщением и не попадает в сохранённый сеанс, чтобы команда не запустилась снова. В режиме захвата кадров экземпляр не ищется, если не задан `ASTER_INSTANCE` (своё имя канала или сокета, им же пользуются тесты).

## Интеграция с системой

Команда палитры `debug-copy-state` копирует размеры сетки, позицию курсора, флаги режима, последние 200 строк истории и текущую видимую область активной панели. Для `debug-save-output` каждая сессия хранит в кольцевом буфере последний 1 МиБ байтов, пропущенных ZMODEM в терминал. Файловые данные протокола и местные уведомления в буфер не попадают. Команда снимает копию, а фоновый поток сохраняет её в папке загрузок под именем `aster-output-<панель>-<время Unix в наносекундах>.bin` и выводит путь или ошибку в исходной панели. Буфер доступен до закрытия панели, в том числе после выхода процесса.

### Интеграция с Windows

- `system.explorer-menu` добавляет «Открыть в Aster» в меню папки, фона папки и диска Проводника: ключи `HKCU\Software\Classes\{Directory\Background,Directory,Drive}\shell\Aster` с командой `"aster.exe" open "%V"`/`"%1"`. При старте ключи переписываются только если пункт включён (путь к exe мог измениться), выключение настройки удаляет их. Пункт «Вставить путь» в меню файла или папки передаёт `aster paste-path "%1"` активному экземпляру. Ядро выбирает кавычки по оболочке и вставляет путь без перевода строки только в активную панель. Если панели нет, открывается профиль по умолчанию. Оба пункта обновляются последовательно в фоновом потоке и удаляются при выключении настройки.
- Перед созданием окна процесс получает AppUserModelID `Aster.Terminal`. На странице «Приложение» можно создать и удалить ярлык `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Aster.lnk`. Фоновый поток сохраняет его через `IShellLinkW` и `IPropertyStore` с тем же идентификатором и исправляет путь при запуске из перемещённой папки.
- Список переходов панели задач строится в ядре из своих и недавних видимых профилей и десяти последних папок, сообщённых активной локальной оболочкой. Папки сохраняются в `session.json`. При запуске и изменениях списка фоновый поток передаёт категории и задачу «Новое окно» в `ICustomDestinationList`, используя AppUserModelID процесса. Команды ярлыков идут через обычный путь CLI.
- Настройка `system.url-scheme` регистрирует `HKCU\Software\Classes\aster` для команды `aster url "%1"`. По умолчанию выключена. Парсер допускает только `aster://profile?profileName=…` и `aster://open?path=…`, декодирует значения в UTF-8 и передаёт существующие команды профиля и папки первичному экземпляру.
- При `terminal.refresh-environment = true` (по умолчанию) новые локальные сессии перечитывают системное и пользовательское окружение Windows. Реестр накладывается на окружение процесса, системный и пользовательский `PATH` объединяются, ссылки `REG_EXPAND_SZ` раскрываются на основе текущих значений. Затем применяются глобальные переменные и переменные профиля. Фоновый поток запускает обычные локальные PTY последовательно, а окно до их готовности сохраняет ввод и последний размер панели.
- `terminal.set-comspec` по умолчанию выключен. При включении в окружение новых локальных оболочек Windows добавляется `ASTER=1`. Дочерние процессы сохраняют командный интерпретатор из `COMSPEC`, который используется для запуска команд с `/c`.

### Журнал

- Журнал пишется в `aster.log` рядом с конфигом (и в stderr); файл больше 1 МБ при старте переименовывается в `aster.log.1`. Команды `report-problem` (новый issue с версией и ОС), `open-log` (папка журнала) и `open-config-file`.

## Обновления

Aster обновляет себя сам из выпусков GitHub. Описание последнего выпуска лежит в `latest.json` (`https://github.com/brano-san/Aster/releases/latest/download/latest.json`): `version`, `notes`, `pub_date`, `platforms.{windows-x86_64,linux-x86_64}.{url,signature}` и `history` — номера и заметки прошлых выпусков.

- **Ядро** (`aster-core::update`). Разбор описания (`parse_manifest_since`: только `https://`, у локального описания ещё `file://`), сравнение версий (числами, выпуск новее своей предварительной версии), base64, `render_manifest` и `platform_of_asset` для подписывающей утилиты. Заметки собираются с учётом истории: если пропущено несколько выпусков, показываются заметки каждого, от нового к старому, без дублей. Запросы `UpdateRequest` (`Check { manual }`, `Install`, `Cancel`) уходят эффектом `Effect::Update`, ответы `UpdateEvent` (`Checked`, `Progress`, `Installing`, `Failed`, `ReadOnly`) возвращаются в `App::on_update`.
- **Интерфейс.** Найденная версия показывает немодальную карточку `UpdateNotice` в правом нижнем углу области содержимого (`view::draw_update_notice`, геометрия в `update::notice_geometry`): «Установить и перезапустить», «Что нового» (заметки из Markdown в простые строки, перенос по ширине, прокрутка колесом) и «Позже». Во время загрузки — полоса прогресса и «Отмена»; ошибка предлагает «Повторить», папка без прав записи — «Открыть страницу загрузки». Клавиатура при этом остаётся у терминала. Ручная проверка («Проверить обновления» в палитре и на странице «Приложение») показывает тост «Проверка обновлений…», затем «Aster X — последняя версия» или ошибку; автоматическая проверка при старте (`[updates] check-automatically`, по умолчанию включена) молчит, если обновлений нет. Тост хранит момент исчезновения, поэтому у тостов разная длительность.
- **Платформа.** `Platform::download` (Windows — WinHTTP с прокси системы, Linux — `curl --proto =https`), прогресс и отмена через обратный вызов; `wait_exit` ждёт завершения процесса; `run_elevated` (Windows, `ShellExecuteExW` с `runas`, отказ в UAC — код 1223); `delete_at_reboot` (`MoveFileExW` с `MOVEFILE_DELAY_UNTIL_REBOOT`).
- **Установка** (`aster::update`, поток `aster-update`). Архив проверяется подписью Ed25519 (`ed25519-dalek`) против открытого ключа, вшитого в `PUBLIC_KEY`. Из zip (Windows) берётся `aster.exe`, из tar.gz (Linux) — `aster` верхнего уровня папки архива. Новый файл пишется как `<exe>.new`, текущий exe переименовывается в первый свободный `<exe>.old`, `.old1`…, затем `.new` становится exe; при ошибке всё откатывается. Подмена идёт в папке exe, поэтому переносная папка `data` рядом с ним не затрагивается. Если папка не записываемая (проба `.aster-update-probe`), на Windows проверенный архив передаётся копии `aster.exe --install-update <архив> <подпись>` с правами администратора: она проверяет подпись ещё раз, подменяет exe и убирает старые копии (занятые — при перезагрузке); на Linux и при отказе в UAC показывается сообщение о папке только для чтения.
- **Перезапуск.** После установки `Handler` сохраняет сессию, отключает значок в области уведомлений и закрывает окна без подтверждения; после выхода цикла окон `relaunch_if_installed` запускает новый exe с `ASTER_RESTARTED_FROM=<pid>`. Новый процесс ждёт выхода старого (`wait_exit`, до 30 с), удаляет `*.old` и восстанавливает вкладки даже при выключенном `terminal.recover-tabs`; проверка при этом старте пропускается.
- **Переменные окружения.** `ASTER_NO_UPDATE` и `ASTER_CAPTURE` запрещают сетевые проверки и загрузки. `ASTER_UPDATE_MANIFEST=<файл>` подставляет локальное описание (его `url` может быть `file:///…`) — так проверяется весь путь без сети, в том числе в снимках кадра.
- **Выпуск.** `tools/aster-sign`: `keygen` (новая пара, секрет — base64 32 байт), `sign <файл>` и `manifest <версия> <дата> <базовый url> <файл заметок> <архивы>…` (ключ из `ASTER_UPDATE_KEY`). Задача `release` в CI при заданном секрете `ASTER_UPDATE_KEY` берёт заметки из текста выпуска, историю — из прошлых выпусков (`gh api`, без черновиков и предварительных), подписывает `aster-X-x86_64-windows.zip` и `aster-X-x86_64-linux.tar.gz` и прикладывает `latest.json` к выпуску; без секрета пишет предупреждение и пропускает шаг.

## Конфигурация

На странице «Терминал» настройка `terminal.identification` управляет окружением новых оболочек. Значение `aster` по умолчанию задаёт `TERM_PROGRAM=Aster` и версию сборки в `TERM_PROGRAM_VERSION`. В режиме `xterm` обе переменные опускаются. Для обоих режимов действуют `TERM=xterm-256color` и `COLORTERM=truecolor`. Явные значения профиля имеют приоритет перед `terminal.env` (прежнее имя `terminal.environment` читается), затем применяются значения по умолчанию. Редактор на странице «Терминал» использует тот же список имя=значение, что и редактор профиля. В локальной оболочке при запуске подставляются `$VAR` и `${VAR}`, в Windows также `%VAR%` без учёта регистра имён. `$$` и `%%` оставляют один знак, неизвестные ссылки сохраняются.

При запуске Aster проверяет наличие папки `data` рядом с исполняемым файлом. Если она есть, приложение хранит в ней `config.toml`, `session.json`, `aster.log` и `window.state`. Обычный каталог настроек — `%APPDATA%\Aster` в Windows и каталог конфигурации Aster в Linux. Команды открытия конфигурации и папки журнала используют выбранный каталог.

`config.toml` создаётся с умолчаниями при первом запуске. Разделы `[terminal]`, `[appearance]`, `[vault]`, `[updates]` (`check-automatically`), `[hotkeys]` (id действий и строки привязок: `"split-right" = ["Ctrl-Shift-S"]`), `[[profiles]]`. Умолчания: копирование при выделении, правый клик — копировать или вставить, 25 000 строк прокрутки.

Экран настроек (`Ctrl-,`, `aster-core::settings`) описан данными: каждый пункт `Setting` — раздел, путь ключа в TOML (`terminal.font-size`), подпись, подсказка и вид элемента (`Toggle`, `Choice`, `Segments`, `Schemes`, `Profiles`, `Number`, `Text`, `StringList`, `Font`, `Run`, `ReadOnly`). Значения читаются и пишутся обобщённо через `toml::Value` (`settings::get`/`set`), так что новый пункт — одна строка в `SETTINGS`; тест проверяет, что каждый путь существует и его тип подходит элементу. Изменение сразу применяется через `App::set_config` и сохраняется эффектом `SaveConfig`; обработчик раздаёт конфиг остальным окнам и заново применяет закрепление и глобальную клавишу. Поиск фильтрует по всем словам запроса в подписи, подсказке, разделе и ключе. За пунктами `SETTINGS` в том же пространстве индексов идут действия (`SettingsPage::shortcut(i)`). На странице «Горячие клавиши» каждая привязка из `Keymap::bindings_of` показана отдельно. Последовательности сохраняют порядок клавиш, например `Ctrl-K Ctrl-C`. Enter или щелчок начинает запись замены всех сочетаний действия, Insert добавляет ещё одно, Del очищает список, Shift+Del возвращает привязки по умолчанию. Пока идёт запись, она получает все клавиши, включая сочетание открытия настроек. При назначении уже занятого сочетания ядро снимает его у предыдущего действия и показывает уведомление.

Общий набор горячих клавиш дополняется привязками для текущей ОС. Windows сохраняет прежние сочетания, а Linux использует Ctrl+Shift+C и Ctrl+Shift+V и назначает переход между панелями на Alt+Shift+H/J/K/L. Записи `[hotkeys]` заменяют наборы отдельных действий и принимают сочетания с кнопками мыши (`MouseMiddle`, `MouseBack`, `MouseForward`), колесом (`Ctrl+WheelUp`, `Ctrl+WheelDown`) и только с модификаторами (`Ctrl-Shift`). Страница сочетаний записывает кнопки и колесо. Сочетание из одних модификаторов срабатывает после отпускания всех клавиш, если за это время не было другого ввода. В режиме отчётов мыши события панели получает программа. Исключение — колесо с зажатым модификатором, когда у этого сочетания есть привязка. Shift со щелчком сохраняет локальное выделение. Экран настроек показывает действующие сочетания, а восстановление удаляет замену и возвращает умолчания текущей ОС.

Настройки открываются отдельной вкладкой: у неё служебная панель `SETTINGS_PANE` (`PaneId::MAX`), которой нет в `panes`, поэтому вкладка не разделяется, не собирается с другими, не попадает в сохранённый сеанс и в закрытые вкладки, а её заголовок — «Настройки». Повторный `Ctrl-,` или Esc закрывают вкладку; если вкладка уже есть, `open_settings` её активирует. `track_tab` после каждого события прячет страницу (`settings` → `settings_stash`), когда активна другая вкладка, и возвращает её с той же страницей, поиском и прокруткой, когда настройки снова активны. Пока страница видна, клавиши идут в неё, кроме действий окна и вкладок (`Action::works_beside_settings`: переключение, новые и закрытые вкладки, палитры, полноэкранный режим, полоса вкладок), если не идёт ввод в поле. Слева список страниц `settings::PAGES` (Приложение, Внешний вид, Цветовая схема, Окно, Профили, Терминал, Буфер обмена и мышь, Поиск, Закреплённое окно, Горячие клавиши, Хранилище, SSH, Файл настроек). При пустом поиске видны пункты только выбранной страницы (`SettingsPage::page`), при поиске — совпадения со всех страниц с заголовками разделов. Страницы переключаются щелчком и Ctrl+PageUp/PageDown. На странице «Цветовая схема» выбирают режим темы и схемы для тёмного и светлого режимов. Ниже перечислены все схемы (сначала свои, затем встроенные), у каждой показаны 16 цветов ANSI на её фоне. Enter или щелчок применяет схему к текущему режиму. Действующая схема помечена словом «Текущая», а при открытии страницы её строка выделяется и прокручивается в область просмотра. Элемент `Control::Run(Action)` — кнопка «Открыть», запускающая действие (папка журнала, файл настроек, отчёт о проблеме). В поле «Цветовая схема» имя проверяется по списку известных схем, а при отрисовке панелей профиля `App::pane_palette` использует указанную схему или схему окна, если поле пусто.

На странице «Внешний вид» собраны шрифты, контраст, лигатуры, размер текста, отступы и курсор. Страница «Окно» управляет прозрачностью, материалом фона, плотностью интерфейса, вкладками, анимациями и значком в области уведомлений. Положение настройки на экране задаёт её раздел в `SETTINGS`, путь ключа в TOML сохраняется.

`Control::Segments` показывает варианты рядом и выделяет текущий цветом акцента. Ширины кнопок вычисляются по переведённым подписям, общая ширина ограничена 55 % строки и 360 единицами в масштабе интерфейса. Геометрия кнопок используется и при обработке щелчка. Стрелки влево и вправо переключают варианты с клавиатуры.

`Control::Font` ищет подстроку без учёта регистра и предлагает до восьми семейств. Для основного и запасного шрифтов терминала выбираются моноширинные семейства, для интерфейса доступны все. Обработчик получает каталоги через `Platform::font_families` в фоновом потоке и передаёт их ядру через `App::set_font_families`. В Windows источник данных — системная коллекция DirectWrite, в Linux — fontconfig. Стрелки вверх и вниз меняют подсвеченный вариант, Enter или щелчок принимает его.

В заголовке страницы «Приложение» показана версия сборки. Кнопки открывают описание установленного выпуска и страницу последнего выпуска. Далее расположены действия для открытия журнала и файла конфигурации.

На странице «Файл настроек» видны путь к активному `config.toml` и результат его чтения и разбора с диска. Обработчик обновляет статус при открытии настроек и перезагрузке конфигурации и передаёт ошибку через `App::set_config_status`. Ошибка TOML указывает строку и столбец. Действия страницы открывают файл, его папку или файл с настройками по умолчанию. Последний записывается в `defaults.toml` рядом с конфигурацией из `Config::default().to_text()`.

Контекстные меню (`aster-core::menu`) — список `Entry` с действиями `Action`, поэтому каждый пункт доступен и из палитры команд, и через горячую клавишу; подсказка справа — текущая привязка. Палитра строит дополнительные строки из тех же записей меню, например «Вкладка > Закрыть другие вкладки». Поиск принимает исходный английский путь и перевод. В `palette.hidden-commands` перечисляются идентификаторы действий, которые скрываются вместе со всеми путями меню. Горячие клавиши и сами меню остаются доступны. Действия управления профилями, очистки списка недавних, сворачивания, разворачивания и закрытия окна доступны через тот же каталог. Команда выхода Windows использует существующий маршрут меню области уведомлений с сохранением сеанса и подтверждением закрытия. Меню вкладки открывается правым щелчком по ней (вкладка сначала становится активной, действия работают с активной), меню терминала — правым щелчком при `right-click = "menu"`. Двойной щелчок по вкладке или `rename-tab` открывает поле имени прямо во вкладке; своё имя хранится в `Tab::title`, пустое возвращает заголовок от оболочки, и оно переживает восстановление сессии.

Команда `export-buffer` снимает текст истории и экрана активной панели. Эффект `ExportBuffer` передаёт снимок обработчику окна, фоновый поток создаёт в папке загрузок файл UTF-8 `aster-buffer-<панель>-<время>.txt` и печатает приглушённое сообщение с путём в исходной панели.

При `terminal.copy-as-html` ядро строит для выделения фрагмент `<pre>` с цветами палитры панели и полужирным начертанием. В Windows окно публикует обычный текст и зарегистрированный формат HTML с байтовыми границами фрагмента. В Linux в буфер обмена передаётся обычный текст.

При `terminal.paste-newlines-as-spaces = true` обработчик `App::paste` заменяет каждый перенос строки (CRLF, CR или LF) одним пробелом до проверки многострочного текста, удаления крайних пробелов и кодирования bracketed paste. По умолчанию переносы сохраняются.

Вставка нескольких строк (`aster-core::paste`) сначала показывает окно с превью и кнопками «вставить», «одной строкой», «отмена», но только если программа не включила bracketed paste: тогда оболочка выполнила бы каждую строку сразу. Отключается `terminal.warn-on-multiline-paste`.

Колокольчик (`terminal.bell`): `visual` — короткая подсветка панели (150 мс, таймер окна), `audible` — эффект `Beep`, системный звук через `Platform::beep`; где звука нет (Linux), обработчик вместо него подсвечивает панель. Звонки чаще раза в 250 мс сливаются в один. В фоновом окне эффект `Attention` дополнительно запрашивает мигание кнопки на панели задач, если включён `terminal.bell-attention` (по умолчанию).

Переключатель `appearance.animations` по умолчанию включён. При выключении исчезают всплывающие названия вкладок, курсор перестаёт мигать даже при включённом `terminal.cursor-blink`, а визуальный звонок в активном окне запрашивает внимание через панель задач. В фоне этот запрос управляется `terminal.bell-attention`. Звуковой звонок по-прежнему использует системный звук.

Прозрачность: цвета `DrawList` хранятся без предумножения, вершинный шейдер умножает цвет на альфу, смешивание `ONE, INV_SRC_ALPHA`, цепочка обмена DirectComposition создаётся с `DXGI_ALPHA_MODE_PREMULTIPLIED`, цвет очистки предумножается. App при создании и при смене `appearance.backdrop` выдаёт эффект `Surface`; окно отвечает `Window::set_surface`, что получилось: `translucent` (Windows — да; Linux — если у EGL есть конфиг с 8-битной альфой, поддерживающий прозрачность: на Wayland окно создаётся с `with_transparent`, на X11 ещё и с visual этого конфига, иначе окно остаётся непрозрачным) и `backdrop` (Windows 11: `DWMWA_SYSTEMBACKDROP_TYPE` — Mica `MAINWINDOW`, Acrylic `TRANSIENTWINDOW`; Windows 10 отказывает). `App::restyle` даёт фону терминала альфу `appearance.opacity`, а полосе вкладок — 0 при материале, иначе ту же. Кадр очищается полностью прозрачным цветом, а полоса вкладок и область терминала закрашиваются по разу, чтобы полупрозрачные слои не складывались. Окно без поверхности перенаправления (`WS_EX_NOREDIRECTIONBITMAP`), поэтому материал виден сквозь прозрачные пиксели без `DwmExtendFrameIntoClientArea`; с расширением рамки DWM рисует под заголовком свои кнопки. Экран настроек, превью и поле переименования рисуются непрозрачным `theme.surface`.

## Linux

При закрытии панели вся группа процессов оболочки сразу получает SIGHUP и SIGCONT, а отдельный короткоживущий поток отправляет группе SIGTERM через 1 с и SIGKILL ещё через 2 с, если в ней остаются процессы, поэтому интерфейс не ждёт.

Окно без системной рамки: `HitArea::Caption` превращается в `drag_window`, полоса в 5 пикселей у края — в `drag_resize_window`, двойной щелчок по заголовку — в разворот, правый щелчок — в меню окна. Клавиши сопоставляются по позиции на US-раскладке (хоткеи работают на любой раскладке), текст берётся из `KeyEvent::text`; при зажатом Ctrl окно само порождает управляющий символ (Ctrl+C → 0x03), при Alt — `AltChar`. Буфер обмена асинхронный: `clipboard_text` просит winit прочитать данные, номер запроса связывает ответ с исходным окном. Обычная вставка приходит событием `Pasted`, а вставка мастер-пароля — `VaultPasted` с идентификатором поля. Если поле уже закрыто или начат следующий шаг ввода, ядро отбрасывает ответ. Таймер мигания курсора — `ControlFlow::WaitUntil`.

Устройство OpenGL ES одно на процесс и создаётся от дисплея цикла событий; на Wayland вертикальная синхронизация отключена (кадры темпирует композитор), на X11 — `SwapInterval::Wait(1)`. Иконки интерфейса — `AsterIcons.ttf` (подмножество Fluent UI System Icons на кодах Segoe Fluent), шрифт интерфейса по умолчанию — `AsterSans.ttf` (подмножество DejaVu Sans) или шрифт рабочего стола из GNOME/KDE.

## Проверка кадра без экрана

`ASTER_CAPTURE=путь.png` после каждого кадра пишет снимок и завершает процесс через `ASTER_CAPTURE_MS` (по умолчанию 4 с); на Windows окно открывается вне экрана, на Linux — обычным окном. Тест `crates/aster-platform-linux/test/render.rs` рисует кадр `App` на безоконном EGL-устройстве в offscreen-текстуру и с `ASTER_RENDER_PNG=путь` сохраняет его. `ASTER_CAPTURE_SIZE=900,520` задаёт размер, `ASTER_CAPTURE_KEYS` — ввод: `'текст` печатает символы, `Ctrl+Shift+S`, `Enter` и т. п. — клавиши. `Wait` делает паузу 1,5 с, `Click@x,y`, `RightClick@x,y`, `DoubleClick@x,y` и `MiddleClick@x,y` — щелчки в пикселях клиентской области (только Windows). Пример: `ASTER_CAPTURE_KEYS="'cd C:\Windows;Enter;Wait;Ctrl+Shift+D"`.

## Тесты

- `aster-gfx` — список примитивов, атлас и текстовый кэш.
- `aster-vt` — печать, перенос, OSC, ответы DA, OSC 52, прокрутка, выделение, reflow, режимы, палитра.
- `aster-core` — разбор привязок и аккорды, кодирование клавиш, мыши и вставки, конфиг, дерево панелей, селектор, сценарии `App`.
- `aster-platform-windows` — кавычки аргументов, блок окружения, настоящий запуск `cmd.exe` через ConPTY с кодом выхода.
